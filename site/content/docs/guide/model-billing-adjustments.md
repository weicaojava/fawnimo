---
title: 核对更正账单和歧义调用
description: 使用新凭证记入更正后总额，或明确选择同一请求标识对应的历史调用。
---

先按[账单核对指南](../model-billing/)停用对应网关和工作进程，确认已有所有者、固定数据目录及新版本账目结构。不要操作原用户目录来试验；可先在独立预览数据中验证。维护命令不会调用模型、提高项目预算或请求供应商退款。

## 更正、退减或补记

保留新原始凭证，并按原规范导入另一份 `statement_key`。CSV 的 `amount_minor` 是该请求的**更正后总金额（整数分）**，不是差额。例如原来12分、现在5分，填5；完全不收费时必须明确为 `not_charged, CNY, 0`。缺少一行、任务失败或取消不能当作退减依据。

导入时原结算已存在，金额不同会保留冲突，不会覆盖。维护者在私有账目中核对新行、原收据及其项目；原收据和新行必须具有相同的历史账户、连接版本、请求和币种。随后明确提交当前更正版本，首次为0：

```text
python reconcile_model_billing.py --root <identity-root> --account <existing-owner> --correct-line <new-line-id> --reference-receipt <original-receipt-id> --expected-correction-revision 0 --reason "已核对原凭证和更正总金额"
```

成功结果返回更正编号和新版本。下一份更正使用已观察的新版本；遇到版本冲突先核对当前记录，不自动重试猜测。相同原操作可以重放，不会重复退减或补记；后来有更正时，旧操作恢复仍返回其原结果。

退减释放当前项目的已结算占用，原收据和任务明细保持原事实。这只是记录已确认账单的变化，**不表示供应商退款已到账**。补记只使用原项目现有额度，额度不足时保留争议和完整新金额。需要增加授权时，所有者须先在该项目“设置 → 项目预算”中明确调整，再恢复同一核对操作。不要改数据库余额或伪造零费用绕过。

不同金额不能用“确认重复”命令代替；金额未变则继续使用原来的完全重复凭证核对。已更正的同一行不能重新归类为重复记录。曾经超过原报价的事实不因退减而消失，后续调用仍须核对受信费用上界。

## 多个调用共用请求标识

先正常核对账单，确认结果为 `ambiguous`。在私有账目中逐一核对实际候选调用与其项目；只有真实匹配、仍保留未知预留且尚未结算的调用可选：

```text
python reconcile_model_billing.py --root <identity-root> --account <existing-owner> --assign-line <ambiguous-line-id> --charge-id <selected-original-call-id> --reason "已人工核对这份凭证对应的原调用"
```

命令固定选择并沿原流程核对该调用。相同选择重放复用原决定；不能将其改归另一项目或调用。其他候选继续保留未知费用，需要各自明确证据，不能因为已选其中一个就批量释放。

## 查看和恢复

项目预算显示首次核对金额、更正后账单金额、累计退减、累计补记及更正条数。当前已结算额与剩余额度使用净变化；下方任务明细保留原结算，另一项目的额度不受影响。新的未决负债按当前净额计算差额。

原账单恢复仍使用 `--statement-id`；已更正行返回 `correction_applied`，不再次入账。不要删除历史来恢复。原始证据、人工归属和金额核对均不等于供应商自动认证，`provider_bill_verified` 仍为 false。真实账单、退款到账、收费生成、独立审核及公网验收均继续待验。
