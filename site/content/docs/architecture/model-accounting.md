# 模型费用与账单

模型费用基础复用单个项目的 `execution_budgets` / `execution_budget_entries`，没有工作空间总上限。当前仅支持 SQLite。顺序文本工作流、文本连接测试、单张文本图片候选及原片视觉/ASR理解已接入单独运行器的项目准入、发送准备和响应证据。身份网关的收费门禁仍关闭。持久原生视频继续使用现有独立准入，不自动取得通用账单关联。

## 连接与报价

`provider_connection_versions` 在实际供应商新增、修改、删除事务内单调推进，无旧记录的连接视为版本0。删除后保留版本墓碑，同ID重建不会重新匹配旧任务。SQLite触发器同时拒绝回退、删除和替换时钟。文本/图像执行在同一查询中读取模型、供应商、版本和临时密钥；版本进入安全绑定，密钥仅用于该次内存调用。已排队旧绑定遇到连接变化时失败，不改向新凭据。

受信 `ModelPriceConfiguration` 默认关闭。规则显式指定调用类型、库内模型ID、实际请求模型名称 `model_name`、供应商连接版本、账户版本、人民币单次费用上界及依据；未知、零价、冲突、过大或带未知字段的配置不通过。启动时从受信服务器路径读取有界配置，文本和图片运行器共享同一只读策略。单独工作室使用 `MODEL_PRICE_CONFIG`；固定身份进程仅接受自身 `private/model-prices.json`，不继承主机价格路径。导入且锁定的空间不加载价格。文件或父路径重定向、非法内容均保持关闭，不向页面输出文件内容或错误细节。

实际请求名称进入新报价指纹与批次清单。只修改库内模型名称不会改变供应商账户时钟，因此可用性、原子预留和发送准备均另外精确核对当前名称；同一逻辑ID不能沿用另一个请求模型的报价。新预留与准备读取最新数据库元数据，残留ORM实例不能绕过检查。旧报价缺少名称时只保留历史解析：序列化省略新增空字段，旧指纹、清单、已接受任务重放和实际账单关联仍可核对，不回填旧授权，也不允许凭它发出新HTTP。升级价格文件或更换模型名称后须重新核对并确认新报价。

可用性只读接口返回本协议的单次上界和完整策略指纹。`agent_text`、`model_connection_test`、`asset_image`、`video_vision`、`video_asr` 分别登记，即使同一模型也不互相推断报价。网页须确认精确指纹，不能提交自己的金额；过期指纹返回409。固定身份网关保留既有收费提交门禁；填写价格文件不会开放它。测试金额不代表真实供应商价格。

## 原子预留与发送证据

`reserve_in_transaction` 供持有 `BEGIN IMMEDIATE` 的服务调用；一次保存1至64个调用的整批清单、可信提交人、项目、报价快照与预留。额度不足会连同同事务任务一起回滚。同范围键与完全相同清单重放复用旧记录，换项目、操作者或报价会冲突。另一项目的额度不被占用。

每个 `ModelCallCharge` 固定调用与历史连接身份。`prepare_call` 只允许一次CAS取得发送许可，并先将预留标为费用未知；未知结果、取消意图、就绪输出和缺少账单都不能退款。响应请求标识只是接收证据，不是实际费用。只有仍未发送的 `planned` 单位可以释放。批次、调用身份及账单证据的保护同时覆盖更新、删除和 SQLite `REPLACE` 的主键/自然唯一键冲突。

`model_job_charges` 将完整批次绑定到真实 Agent 或图片 attempt。准入在首次读取幂等标识前取得写锁，任务、完整节点计划、费用单位和原项目绑定在同一事务保存；额度不足不留下半个任务。绑定插入同时核对完整节点费用集合，已绑定批次不能追加调用。已收费绑定的任务身份、输入快照、节点身份和计划不可改删或替换。无绑定的旧历史仍可读，但排队任务不能自动获得新的费用许可。

工作进程在任何节点发送前，重新核对整批的范围、提交人、项目、完整单元集合、协议/模型/连接/账户、报价与项目明细、绑定摘要和清单摘要；错误维护插入的不完整计划也不能先发一部分请求。每次 HTTP 前另核对有效租约、同快照连接版本及当前策略指纹，提交未知预留后再发送。响应头中经过格式检查的 `x-request-id` 仅写入私有费用账目，不从内容ID推断请求身份，也不向业务读取接口返回。取消、失败、连接或策略变化、过期租约只释放未发送单位。显式重试新建完整预留，固定原项目与原模型连接，保留原来的未知费用；全局资产被多个项目引用也不改变当次选定的费用项目。候选采用不创建新调用或新预留。

界面要求显式选择费用项目并显示完整预留；文本工作流按所有LLM节点汇总，连接测试采用其独立报价，单张图片只预留一次。余额展示计入待核对账单，后端仍在写事务内最终判断。当前业务页面分别保留未确认提交的原路径、内容和标识，提供独立的手动恢复动作：原任务已用满额度、当前选择另一个项目或修改输入也可精确重放原授权，服务器优先返回原记录；未曾接收时仍执行原报价及预算准入。累计8项未确认后暂停创建更多。刷新、离开该业务或跨设备后应先查历史，不宣称浏览器本地标识已持久恢复。

理解任务使用独立 `understanding_attempt_charges`，以真实job/attempt/project复合身份绑定完整批次，不修改已有 Agent/图片绑定表的协议约束。有音轨且开启转写时一次预留ASR与视觉，否则只预留视觉；缺少一项或额度不足则实际任务、尝试及费用全部回滚。发送每项前检查整次计划及所有相关账单门禁，前序ASR已结算但报价超界时也停止后续视觉。取消只释放未发送单位，显式重试固定原项目/来源/连接并再预留完整计划。

理解页固定当前项目，不提供改归其他费用项目的重试。其单个未确认意图按当前空间、项目和分析范围保存，包含首次提交或重试的原请求内容；刷新后的手动核对仍先返回已接受记录，不受当前表单、旧尝试号或已用满额度影响。短DB操作会完成并等待事务及会话关闭后再传播取消，HTTP和解码仍独立可中断；认领刚提交即停止也会立即释放尚未发送计划。完整行为见[原片理解架构](../video-understanding/)。

## 人工账单核对

离线工具保存私有原始文件与规范化CSV，数据库记录两份证据的哈希、明确供应商/连接/账户版本及操作人。不自动认证供应商，不根据生成内容、usage、任务失败或账单缺行猜金额。

一行必须精确匹配一个历史账户和保存的供应商请求标识。缺失或多义匹配保留未知预留；每次调用、每个账单行仅有一个最终收据。同一来源键重复导入复用原记录，改变原证据或金额不能覆盖历史。只有明确 `not_charged` 且金额0的匹配行可释放；`charged` 金额0仍作为显式已结算记录。

实际账单超过原报价时保留全额：已有授权余量足够，则原预留结算到原报价，额外部分写入独立差额记录，收据同时绑定两部分；不足则保留全额账单和原未知预留，暂停该项目新调用，等待所有者显式补足上限后重新核对。原报价指纹被标为超界，换一条仍低于已观察金额的报价也不能绕过。发送准备也重新检查这项保护：账单在整批准入后才到达时，尚未发送的预留不能继续使用失效报价或绕过未决争议。

规范化金额表示单个请求的总费用。多份重叠未决证据按调用取最高观察总额，扣除该调用已结算全额或仍持有的预留，避免重复占额度；所有行和争议历史仍保留。已核对调用再次出现账单行会产生冲突。只有账户、请求、收费状态、币种、金额完全一致，且明确引用原收据的人工决定，才可确认“重复证据”。决定不可改删，不新记费用。不同金额更正、退款与多义请求目前保持未决，未提供隐式合并或差额冲销。

## 私有维护边界

`reconcile_model_billing.py` 要求已存在的有效所有者、固定空间标记、网关根锁和工作进程锁。未完成认领的持久迁移日志也会阻止导入，避免破坏中断恢复。账单文件位于固定空间 `files/billing-evidence/`，不注册为素材，不可从素材列表/下载接口读取；路径跳转和覆盖不同字节均拒绝。现有完整files离线备份包含这些文件，因此备份也应保持私有。

预算API的账单总额、观察金额、待补金额与计入账单后的余额使用精确十进制字符串；流式Python整数汇总避免大额证据导致SQL聚合溢出。读快照使并发核对不能拼接旧账单与新余额。

本地自作账单、HTTP夹具、进程及浏览器检查只验证上述软件行为。真实供应商账单认证、所有模型运行时接线、全收费执行隔离、模型质量、完整成片和公网资格仍独立待验。F-001.04、F-009.03继续为部分实现。
