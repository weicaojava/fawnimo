---
title: 候选草稿 PR 发布与追溯
description: 默认关闭的维护者发布入口、准确候选绑定和中断后的只读核对。
---

`github_candidate_publication_v1` 是独立于个人视频空间的维护者服务。它将已有的公开惰性提案、准确本地候选和已通过且确认清理的固定 Linux 检查绑定到同仓库草稿 PR。策略默认关闭；不调用模型，不提交审查，不合并，不部署。产品候选的真实 GitHub App、真实来源到 PR 的联合验收和独立审查仍未通过，不能用本机自作远端事实替代。

策略固定仓库数字身份/名称、可信检查镜像 ID、当前可信父程序 SHA-256 和两个准确工作流 blob。输入只有稳定请求键、原变更包编号和原检查编号。候选不能提供目的地址、分支覆盖、令牌、命令、审查结论或发布权限。仓库、需求和候选均须属于相同公开来源。

新操作先检查原公开需求、评估/计划选择/准备、公开 main、功能登记、候选提交/树和原通过检查。创建 Git 对象、新分支和 PR 之前分别复查来源和远端 main；外部操作均在数据库写事务之外。并发状态无法与 GitHub 原子提交：观察后发生的需求撤回/main 推进可能留下已有分支或草稿，因此最终准确 PR/审查/CI 必须另行重新观察，发布记录不具有继续行动权限。

候选 Git 对象来自已提交的公开对象，使用独立索引的既有核对，不读入维护者暂存、未暂存或未跟踪资料。原提交的消息、父提交、树、作者/提交者、时间和时区投影到 GitHub Git Data API；逐个核对 blob、树和提交 SHA。远端编码差异导致提交 SHA 不同时立即停止，不重建另一候选冒充原检查。只创建原 `community/change-<变更包前24位>` 新分支，没有更新、强推、删除分支或推送 main 的接口。

PR 固定为同仓库、原候选头、main 基础的草稿，标题和正文只含固定说明及公开追溯编号，不采用需求文字作为指令或发布文案。已有分支/PR 必须准确匹配；不同提交、关闭的 PR、改变的基础/头或重复 PR 都进入待核对状态，不覆盖或创建替代。发布不等于 CI 已触发或通过，记录中的 `ci_qualified` 始终为 false；后续使用[准确 PR 观察](../community-pr-gates/)获取真实结果。

独立根目录仅有 `publication.sqlite3` 及其 SQLite 伴生文件，三个业务表保存固定策略、原意图和显式递增序号事件。原请求键、变更包、逻辑/物理键替换以及更新/删除均受约束；最多 64 个原发布、512 事件、16 MiB JSON。历史顺序使用声明的序号，VACUUM 不重排。策略不原地改写，需要新根目录。

唯一抢占成功的控制器先保存意图，再创建外部资源。新分支/PR 的尝试先记 `ref_intent` / `pr_intent`，只有明确读回准确结果才记完成。响应丢失、异常或控制器退出后，原请求重放只返回历史；不会再次发送 POST。显式只读核对可确认已有原分支/草稿，未发现资源不表示原请求必然未被接收，也不授权重试。未知结果可能需要维护者人工处理，服务不会自动删除遗留资源。

认证仅由维护者明确提供的独立 GitHub 凭据文件读取，文件内容不进入策略、审计、候选进程或输出。控制器固定访问 `api.github.com`，不跟随重定向，不读取个人模型密钥、环境令牌或 Git 凭据管理器。每个连接有超时，响应上限 1 MiB、请求上限 48，后续请求受 90 秒时钟预算约束；这不是抗同机管理员或网络层强制终止的保证。数据库/Git/维护者与 GitHub 受信。

本地验证使用实际临时 Git、SQLite、并发线程和独立 CLI 进程；GitHub/内核通过事实来自明确自作的测试数据。它证明有界软件路径，不证明真实 App、实际收费、独立审查或公网交付。
