# 本机视频生成配置与工程预算

默认本地工作区仍使用无凭据、无执行能力的准备目录。只有主机明确提供 `VIDEO_RUNTIME_CONFIG` 文件或启动参数 `--video-config`，且文件 `enabled=true`、单次费用预留及依据有效、专用环境凭据存在，应用才构造并启动实际 `ExecutionRuntime`。构造只进行本地配置检查，不发模型请求；数据库扫描器也只处理已由明确提交进入队列且绑定相同配置的任务。

本机配置文件遵守 `VideoRuntimeConfiguration`，不允许 JSON 内的密钥、端点或下载主机覆盖。密钥只从显式命名的环境变量读取，不回显到模板、状态、配置指纹或日志。文件无效时返回固定状态说明并保留手工项目功能。服务和账号版本进入持久绑定，更换版本后必须重新编译新计划；旧任务仍保留原身份与预算，不重新提交。

当前视频协议沿用受限文本生成档案：`doubao-seedance-2-5-260628`、4至30整数秒、9:16、480p、MP4、无生成音频、保留水印。它不支持参考图片/视频/音频；当前人物参考图不会被静默丢弃后提交。准备档案和已保存的历史预览保持原语义，新配置不授予真实模型或成片质量资格。

`GET /video-runtime/setup` 返回无密钥的配置状态。`/video-runtime/configuration-template` 下载默认关闭、报价未知的模板。生成服务可运行也不会启用旧 Film/Celery 动作；公开字段 `legacy_actions_available` 始终为 false，旧入口与新的受信计划提交是不同执行通道。

准备计划与可执行计划按不可变绑定区分，不能仅按相同模型ID永久禁用全部计划，也不能因主机后来启用而自动放开旧准备记录。原S25A准备档案与准备预览始终保持不执行语义；数值预留且匹配当前受信配置的新计划改用 `GET /video-runtime/projects/{project_id}/plans/{plan_id}/request-preview` 检查实际wire body。该GET不建任务、不预留费用、不访问模型，仍固定 `can_submit=false`、`model_qualified=false`；页面提交须同时通过独立服务器preflight、当前同计划/内容hash预览以及明确确认。原请求恢复优先核对已有任务，不自动新建调用。人民币预留统一显示元，服务账本仍使用整数分。

## 工程预算

`GET/PUT /video-runtime/projects/{project_id}/budget` 读取和保存人民币累计上限。保存仅改变上限：使用 SQLite `BEGIN IMMEDIATE` 和版本 CAS，不清除已预留、已结算或接收未知的记录。新上限不得小于已预留与已结算之和；未登记工程返回可准备但没有可用额度的明确状态。接口返回账本修订、可预留余额、未结清任务数和未知接收任务数。

界面入口位于工程“资产版本”中的“执行任务 → 视频服务与工程预算”。保存预算不会创建任务、放开旧计划、释放未知费用或产生模型调用。应用账本尚未与供应商真实账单对账；单次预留值是经管理员核对后登记的受信值，不能将其或 `spent_minor=0` 当成实际账单或免费证明。

## 实际软件闭环

身份网关中的空间 worker 另有所有工程共用的[工作空间视频预算](/docs/architecture/workspace-budget/)，初始为零，预留同时受两层限制。原独立本地模式仍保留工程账本行为；空间预算不从旧模式自动认领数据或额度。

启用后的计划继续使用已有编译、逐镜显式提交、预算准入、持久唯一发送、原任务查询/下载与文件发布。就绪文件是候选，采用仍通过剪辑页独立确认并记录不可变计划、镜头、资产版本和任务来源。采用和媒体可解码不代表画面质量或供应商费用已经核验。

隔离验收运行实际本地 HTTP、SQLite、真实 MP4 下载与解码、逐镜提交和显式采用；重复同请求只返回原任务，媒体就绪前后都不自动采用。本地图片/视频夹具不属于真实模型生成结果。界面预算另覆盖保存、刷新、并发冲突保留输入、读取新修订、下载默认关闭的模板以及亮暗主题。
