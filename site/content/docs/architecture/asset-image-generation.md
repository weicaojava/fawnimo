# 全局资产图片候选与明确采用

演员、服装、场景和道具编辑页提供独立的“文本生成图片”入口，使用 `/api/v1/asset-image-generation` 与生成的 `AssetImageGenerationService`。它不经过旧 Film/Celery 图片任务，也不借用视频执行可用性。角色实例、视频参考图和人物一致性不属于此入口的支持范围。

## 模型配置与协议

用户在模型管理的图片模型编辑表单开启“用于本机单张图片生成”。保存时内部设置 `model.params.asset_image_protocol=openai_b64_v1`；关闭只删除该键，保留其他参数。JSON 非法或不是对象时拒绝保存并保留输入。供应商须配置为受支持的 OpenAI-compatible 图片供应商。开关、配置保存、页面打开与历史读取不自动测试模型。

确认生成后只向配置的 `/images/generations` 发送 `model`、用户提示词、尺寸、`n=1`、`response_format=b64_json`。支持 256、512、1024 方形尺寸参数。该路径不发送现有人物图片、不接受调用方的 URL、headers、供应商地址或任意生成参数。仅接受 `data` 中恰好一张 `b64_json`；URL-only、同时带 URL、多张图、坏 base64 和无法解码图片均失败，绝不补做图片网址下载。

当前适配器支持声明的单张 base64 协议，不保证任意供应商或模型都实现它。真实模型账号、画面质量和人物一致性需要另行验收。

## 持久任务和不可变结果

`asset_image_generation_jobs` 固化资产类型、资产与槽位、提示词、模型绑定、尺寸和幂等标识。相同作用域与标识、相同参数返回原任务；改变参数拒绝。SQLite 普通请求事务内使用原生 conflict-safe INSERT，提交前工作进程无法发现任务。

工作进程使用 queued→running 的 CAS 租约，只发送一次真实 HTTP。所有结果、失败和发布均要求状态、令牌及有效期仍匹配。超时或中断成为明确的未知失败，不自动重新发送。显式取消会终止网络进程，迟到图片不发布；已发出的远端请求仍可能计费。失败与取消只有明确确认可能重复费用后才创建新 attempt，原历史保留。

响应有 HTTP、base64、8 MiB 解码字节、4096 边长及 1600 万像素边界。Pillow 实际解码单帧 PNG/JPEG，并根据真实 bytes 计算 SHA、尺寸和 MIME。候选文件位于本地受限根目录下，路径含服务器生成的 job UUID、租约 UUID 与 SHA。独占路径通过完整暂存写入、fsync 和原子 hard-link 发布；随后有效租约 CAS 才让其内容端点可见。失去租约的私有暂存结果不成为候选。

SQLite 触发器保护请求身份和候选结果字段，成功任务不可删除；采用后的文件与采用身份也不可改。初始化创建表后调用 `migrate_asset_image_generation(engine)` 建立这些约束。当前这个执行入口限 SQLite，不以缺少触发器的其他数据库假称同等保证。

## 候选与槽位采用

编辑页初始化图片槽使用身份型空槽意图：请求原始字段只能包含 `view_angle`、`quality_level`，或使用空对象的默认身份。SQLite/PostgreSQL 以定向 `INSERT ON CONFLICT(owner, quality, angle) DO NOTHING` 原子创建并读回，多个请求可得到同一现有槽，不改已有 file_id、尺寸、格式、主图或其他槽位时钟。带 file_id（即使为 null）、尺寸、格式、primary 或其他额外意图的唯一性冲突仍返回 409，不会伪装为成功，也不用于覆盖原图。本次并发验收使用 SQLite WAL 和两条独立连接。

前端适配器按资产类型、资产、默认精度和角度共享进行中的初始化请求。编辑页在每次异步返回后核对当前加载序号、路由归属及挂载状态，阻止 StrictMode 的旧请求、导航切换和卸载后的后续角度创建或表单回写。已发出的空槽初始化可以完成，但离开该资产后不会继续创建其他角度。前端不通过忽略 409 隐藏后端竞态。

生成完成只产生 candidate，不修改已有图片槽、主图、原文件或其他资产。内容端点只读取本地文件并验证路径约束、字节大小和 SHA，不返回磁盘路径或供应商凭据。

用户采用时先读取目标槽的当前图和时钟，在确认弹窗中查看当前图片，再提交 `expected_file_id`、`expected_updated_at` 与单独的确认。时间转换到 UTC 后比较；在 SQLite `BEGIN IMMEDIATE` 事务内再用精确持久时钟 token 和文件身份作 CAS。槽位在确认期间变化会返回 409。采用只更新原定、同资产槽位的 file_id、尺寸和格式，原文件继续保留，不修改其他槽位或资产主图字段。

采用创建带真实扩展名的 FileItem，逻辑前缀为 `local-asset-image/`。通用文件预览、下载与 ZIP 从该任务的固定本地 bytes 读取并校验，独立于 S3 选择。下载 MIME 与文件扩展名匹配。文件列表不能删除这类不可变任务产物。

这是全局资产候选到槽位的闭环。它不自动将图片变成工程 ProductionMedia，不宣称现有视频执行 profile 支持参考图片，也不覆盖原片拆解的视觉证据。

## 任务回跳

资产编辑支持 `?imageJob=<id>#asset-image-generation`，核对类型、资产和槽位归属后只读取并选择记录。Agent 与模型历史分别支持 `?agentRun=<id>#agent-execution`、`?connectionModel=<id>&connectionRun=<id>`。错误归属或缺失记录显示说明；回跳不会生成、重新测试、重试或采用。

## 本轮验证

隔离 SQLite 与真实 loopback HTTP 覆盖四类资产的 PNG/JPEG、参数协议、并发幂等、取消、显式重试、过期 owner、坏图片与 URL-only 拒绝、SHA 和路径校验、DB 不可变约束、采用 CAS（含 +08:00 时间）及文件 MIME/扩展名。实际浏览器覆盖生成、预览、采用、刷新、冲突、配置开关和安全回跳。外部模型调用、既有模型账号读取及原片修改均为 0。fixture 通过只证明软件链路，不等同真实模型质量通过。
