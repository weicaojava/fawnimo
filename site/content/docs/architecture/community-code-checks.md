---
title: 社区候选代码检查
description: 单独启用的固定 Linux 检查协议、持久执行记录与确认清理。
---

`linux_pytest_check_v1` 是维护者明确启用的独立代码检查程序。准备租约、惰性变更包和本地 Git 提交都不会自动启动它。输入只接受已有变更包编号与原请求键；镜像由本机维护者选择准确的本地镜像 ID，输入中没有命令、网络、主机挂载、凭据或审核许可字段。此阶段为作者审阅的软件实现；真实 Linux/OCI 能力另由准确提交的容器验收记录证明，不能用本机契约测试替代。

新检查重新读取固定公开需求和 `main`，核对准确准备记录、评估/计划/选择修订号、登记表以及公开 Git 提交、树和源码对象。网络、Git 和 Docker 元数据读取在 SQLite 写事务之外；最后在需求库短写事务中复查当前来源/选择并向独立变更库预留一次执行。旧请求恢复先于这些新操作门槛，只返回原记录，不重复创建或启动。

候选和基础版本的完整源码/资源清单来自已提交的 Git 树。镜像中的对应全部文件必须逐字节匹配基础清单，应用变更后全部文件必须匹配候选清单。只核对改动文件、使用旧镜像里的测试或采用维护者工作树都不能通过。控制器、可信检查程序、审核规则、CI 和依赖仍不在候选修改权限内。

独立变更库明确启用后由两张提案表扩展为五张业务表，另三张保存固定策略、执行身份和追加事件。SQLite 内部序列表不计入业务表数。并发固定为一，每个变更包最多三次、整个库最多 384 次，事件容量 4096；外部费用授权固定为零。逻辑键与物理 rowid 替换均受保护。旧代码不会识别此扩展；升级和回退需保留一致备份及新历史，不能删除执行表伪装成旧库。

事件顺序包含 `allocated → create_requested → created → start_requested → observed → terminal`，另有取消意图和待清理记录。先提交外部操作意图，再调用 Docker。创建/启动应答未知时不自动重放；租期结束、程序退出和资源暂时不可见都不能释放执行名额。创建尚未得到具体容器身份时，成功查询到“没有容器”仍不能证明请求未被接受，必须保留原预留。发现准确原容器后才可记录身份、清理并结算。

每次 Docker 操作用独立空白 CLI 配置和选定的本地端点，避免继承个人配置中的认证、代理或请求头。拒绝远程端点、环境覆盖和缺少必要能力的引擎，不拉取镜像。固定容器无主机挂载、Docker 套接字、公开端口或外部网络；镜像只读，临时目录 128 MiB、共享内存 1 MiB、内存 512 MiB、交换空间零、CPU 一核、进程 64、文件句柄 128、core 文件零，禁用自动重启和健康命令，并限制日志大小。实际配置在启动前后读取核对，内核限制还要在容器内证明。

容器里的可信父程序只使用标准库，不导入应用或候选代码。它在读输入前安装独立 60 秒硬时限，核对自己的源码哈希、只读镜像、真实 cgroup、能力位、seccomp 和断网状态，复制并封存准确公开源码。候选 pytest 子进程使用 UID/GID 10001、空附加组、零有效能力和禁止新增权限；父程序先从内核核对身份，才打开输入门。候选最多运行 45 秒，并为原控制程序的硬时限留出报告时间。合并输出最多保留 64 KiB；超量、失败、超时或未结束的后代均不能记为通过。可信结果通道与候选输出分开，候选打印“审核通过”不能改写父程序报告。

取消先持久保存意图，再结束本次容器。程序强制退出后由明确恢复命令对账，不根据 PID、时间或猜测重建任务。删除前必须同时匹配原随机所有权标记、执行编号、容器名、准确镜像及已有容器 ID；最后确认守护程序中的原资源确实不存在，才写终态并释放名额。其他容器、镜像、卷、网络及个人 Docker 配置不在清理范围。控制程序被强制结束时，其空白临时 CLI 配置目录可能留在操作系统临时区；容器清理凭据不声称清除了所有主机临时文件。

公开记录只保存输出哈希/长度、准确候选版本、结果和清理证明，不保存候选诊断正文或私有清理标记。通过表示本次固定候选测试完成，不授予独立审核、准确 PR 的 CI 晋级、合并、模型费用或部署权限。Docker 守护程序、本机维护者及选定的可信镜像仍在信任边界内；该协议不隔离同一系统身份的恶意维护者。真实公开来源接入、AI 研发、独立审核与 PR 闭环资格分别记录。

操作见[维护指南](../../guide/community-code-checks/)，提案来源见[变更包架构](../community-changes/)，后续门槛见[平台交付计划](../../plans/platform-delivery/)。

当前新提案、公开源码观察和可信父程序统一保护所有 `backend` 根级入口，包括后来增加的控制程序名称；功能登记不能扩大这类修改权限。旧 v1 惰性记录按原完整性规则保留只读、取消和清理能力，但不能据此取得新的执行许可。固定本地日志明确使用单文件 1 MiB、关闭压缩；首次真实 OCI 启动因默认压缩与单文件配置冲突而失败，失败与确认清理记录分别保留。修复后的准确 880c0d9 主分支 CI 后端 1524 通过、2 跳过、2 历史未选择，前端及原通用 Compose40 通过；真实 Linux 隔离10 项、控制程序死亡/无输入时限和确认清理通过。此前 PR 的测试合并树也已与准确头核对相同。该证据不授予独立审查或产品自动发布资格。
