---
title: 本机稳定与预览版本切换
description: 默认关闭的自有容器运行、完整停机快照、新卷回退和中断核对。
---

`local_runtime_release_v1` 由独立维护命令 `manage_runtime_release.py` 提供本机稳定/预览运行。它只创建自己的容器、网络和命名卷，不接管现有服务、主机目录、Docker 凭据或其他业务资源。初始化和状态读取不联系 Docker；启用需明确的镜像 ID、源码提交声明、可信辅助镜像和公开启动文件摘要。源码声明和镜像标签用于核对，不等于独立审核、CI 批准或自动上线许可。

稳定版默认使用 `http://127.0.0.1:18080`，预览版默认使用 `http://127.0.0.2:18081`。两个主机地址使浏览器的 host-only 会话 Cookie 分离。首次配置可选不同的新端口，之后来源固定。原有 8000、17888、18000 端口被排除。每个首次运行的环境各自生成全新 A/B 账号、密码、用户和个人空间；不复制另一环境的数据或模型。注册关闭，付费入口仍关闭。

运行要求本地 Linux Docker、cgroup v2 及实际资源限制支持，并要求 Docker Engine 28 或更新版本。客户端使用新建空配置，不继承 Docker 登录、代理或远程端点覆盖；第一次操作绑定具体引擎和端点摘要，后续拒绝切换到另一个引擎。控制程序不构建、拉取或发布镜像，也不启动 Docker。

应用只连接自己的 internal bridge，固定 `gateway_mode_ipv4=isolated`，没有发布端口或默认外网路由。普通 internal 网络仍有主机桥地址，且 internal-only 网络不能直接发布端口，因此访问入口由独立的固定目标代理提供。代理另接自己的前端网络，只发布指定回环地址，关闭 IPv4/IPv6 转发，不挂载数据、账号、Docker socket 或启动代码卷。代理使用可信辅助镜像内的固定公开代码，只接受匹配的 Host，禁止私有就绪路径和内部请求头，不支持 CONNECT、WebSocket 或任意上游地址，不跟随跳转、不读取代理环境。HTTP 并发 8，头部 32 KiB、请求体 70 MiB、响应流 512 MiB；请求读取和响应流分别有 30/120 秒预算，断连时回收连接。

所有容器均为 UID/GID 10001、根文件系统只读、无 capability、无新权限、无主机挂载。应用上限 2 CPU、4 GiB、256 PID；辅助程序和代理为 1 CPU、512 MiB、64 PID；临时区 256 MiB，日志有界。应用仅挂自己的数据卷和只读公开启动文件卷。实际 daemon 配置、镜像 ID/标签/环境、挂载、网络、端口、权限及限制均在操作前核对。镜像应来自维护者信任的构建；本入口不负责把恶意任意镜像变成可信代码。

切换先关闭原代理，再停止原应用及其工作进程。离线检查取得网关和各空间原生锁，读取包含 WAL 的真实 SQLite 快照，拒绝非终态任务、遗留执行租约、未释放项目预留、未确认模型调用、未解决或超价的账单及未知活动表。检查不结算费用、不重试任务、不解密模型连接。已观察到的 Windows `SQLITE_IOERR_TRUNCATE` 只允许在一秒内重新取得全部锁和只读状态；其他错误立即拒绝，持续错误不会变成成功。

原完整网关根目录通过[离线备份规则](../local-releases/)保存到新私有档案卷，包含每个数据库全部行/结构/版本及所有文件摘要。辅助程序在已停止的自有来源卷上只为合作锁写入锁文件，业务数据库以只读方式读取；原媒体、资料和账目不改写。档案清单摘要同时存入维护日志，恢复前逐项验证，不能用修改后的清单替代原档案。部分目标和原意图保留，不会覆盖现有卷。

版本切换和旧数据回退均复制到另一个新数据卷。回退要求相同环境、明确的备份编号、准确当前代次，并确认后来的编辑保留在旧卷。当前与档案的空间/拥有者、用户 ID、身份库结构，以及费用、模型、连接、私有策略、实际 `workspace_identity` 和 `workspace_trial_quota` 指纹必须相同；授权额度或模型记录改变会阻止旧资料回退。

恢复旧业务资料后，另将当前 `control.db` 的完整 SQLite 状态及当前参考视频签名密钥状态带入新副本，保留现在的密码、会话撤销、体验期限、成员和审计，不重新启用旧安全状态。当前密钥不存在时，删除的也只是新副本中的旧密钥。最终目录因此不是旧档案逐字相同的完整回放；记录分别说明旧资料恢复和当前安全状态保留。新旧数据不自动合并，较新的卷始终保留。

公开入口启动前，用私有随机令牌检查选定镜像的网关和最多四个实际固定身份工作进程。新数据代次首次启动后重新核对原业务列/行摘要和非数据库文件字节；只容许保持原业务数据的兼容初始化，破坏旧值的升级拒绝。支持版本下限是已包含音乐混音契约的网关镜像。失败发生在已确认的候选就绪检查时，可以停下候选并恢复原镜像/原数据；原来已停止的版本保持停止。任何未确认的 Docker 接收结果均保留原预约，不能自动重复启动、复制或切换。

维护日志位于源码/Git外的独立私有目录，SQLite FULL 同步，策略、意图、事件、代次、档案和私有就绪配置均追加保存，并防御物理 rowid 的 `INSERT OR REPLACE` 改写。当前指针与成功/停止事件在同一个 SQLite 事务提交。最多 16 次操作、每环境 8 代、16 次策略配置、每操作 128 个事件。旧键先返回历史，不根据今天的策略或引擎状态重新行动。中断可只读 `reconcile`；如需停下相关自有服务，另提交绑定刚观察状态摘要的 `quiesce`，最多三次，保留全部数据/档案。它不自动恢复未知任务、不删除旧卷、不清理未知资源。

初始账号只可导出到源码/Git/维护日志之外的新私有文件，不打印密码、不重置账号。用户修改密码后，旧初始领取文件不会变成重置授权。POSIX 私有根目录 0700、账号/就绪配置 0600；Windows 私有目录 ACL 由维护者配置。

本机单元、真实文件/SQLite与原生工作进程检查和真实 Linux 容器检查分开登记。真实容器工作流单独构建准确源码及已合格的旧源码，验证双环境、A/B、镜像切换、新卷恢复、会话撤销、预算防回退、中断核对、数据保留和自有资源清理；是否通过以对应准确提交的结果为准。既有通用 Compose40/候选检查10不能替代本项验证。公网、真实生产历史切换、掉电故障、真实付费模型、完整成片、真实独立审查和实际 GitHub App 联合自动发布仍各自待验，`automatic_public_promotion` 始终为 false。

网络行为依据 [Docker 端口发布](https://docs.docker.com/engine/network/port-publishing/)和[网络创建文档](https://docs.docker.com/reference/cli/docker/network/create/)。数据准备命令、PR 发布、独立审查观察与本入口分别运行，均不能用本机通过记录替代真实发布门禁。

只读引擎/镜像预检在资源写入前失败会正常终结并保留当前代次，允许明确修正策略；实际写入请求之后的不明结果仍预约。固定IP通过空的自有isolated预约网络取得引擎网段，确认无端点后只删除该预约，再显式创建最终自有子网；地址竞争拒绝，不任意选主机/LAN范围或重复未知操作。创建响应丢失时，完整核对身份后绑定实际资源编号再供明确停止。

所有辅助结果都写入持久目标卷，就绪探针另有独立结果卷、只读业务卷，退出后结果可核对。缺失结果仍保留已核对的进程身份，不自动重跑或标为成功。代理共享连接不保存或返回浏览器Cookie，仅用当前转发头构造请求；Set-Cookie交付对应浏览器，A/B及匿名请求各自独立。

每个新卷首次准备通过后，在业务根目录外写入绑定配置和原始基线的私有凭证。同一已验证代次重启时检查凭证、当前空间拓扑和实际工作进程边界，保留用户正常编辑与项目预算；新激活/恢复目标不复制该凭证，配置/基线/凭证不符会拒绝。凭证只说明本代数据首次准备通过，不是独立审核或发布许可。
