---
title: 章节文本历史与项目设置
description: 当前章节原文、精简文本的实际修订记录，以及项目设置的保存边界。
---

章节原文编辑器使用 `chapter_text_revisions` 保存实际文本修订。每个修订包含原文、精简文本、内容哈希、记录时间、来源和恢复来源。历史不再使用前端预置内容。

新建章节记录初始修订。旧章节读取时返回当前文本和空历史，首次实际保存时才记录当前基线；这些记录的时间是系统保存时间，不代表此前曾经保存过的时间。修改后的内容追加为新修订，相同内容重复保存不会产生重复修订。

原文与精简文本在切换编辑模式时保留各自的未保存内容。点击保存会一起提交两份缓冲区，避免关闭编辑器时遗漏另一种模式中的变更。

接口均位于 `/api/v1/studio/chapters/{chapter_id}`：

| 接口 | 当前行为 |
| --- | --- |
| `GET /text-history` | 返回当前文本、当前修订和按修订倒序的真实分页历史；只读，不创建历史。 |
| `POST /text-history` | 提交 `expected_revision` 和至少一个文本字段，在版本匹配时保存；省略的字段保留。 |
| `POST /text-history/{revision}/restore` | 提交 `expected_revision`，将本章节的指定历史内容复制为新修订，保留原历史及之后的修订。 |
| `PATCH` 章节 | 兼容既有调用方；若修改文本，同一事务内记录修订。 |

新历史保存和恢复使用乐观版本检查。过期编辑返回 `409`，不会覆盖较新的文本；前端保留未提交的编辑内容。SQLite 在写入前取得写锁，读取历史时固定同一读取快照。旧 `PATCH` 接口保留既有参数契约，未提供编辑者版本检查。恢复只能引用当前章节已有的修订，不允许跨章节恢复。

文本历史不自动记录模型任务产生但尚未保存的候选内容，也不伪造人工审核。编辑器中的模型按钮使用运行时可用性检查，检查失败或模型未启用时显示原因并禁用提交；手动编辑、保存和历史恢复继续可用。

项目工作台的设置页通过当前项目的 `GET` 与 `PATCH` 保存名称、简介、视觉风格、题材风格、种子、默认比例和风格继承选项。风格和视频比例候选来自现有后端选项接口。设置页不会跳转到全局设置，也不修改项目资产版本、生成记录或其他项目。
