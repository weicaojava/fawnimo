# 旧工作区迁移、认领与回退

`backend/migrate_workspace.py` 是维护者本机命令，不是注册或项目上传接口。旧 SQLite、完整 `media` 和本地 `files` 先复制到私有备份包；包未认领时不会出现在任何账号中。正式认领必须指定已有且有效的 owner 账号，目标为该账号尚未初始化的个人空间目录。已有目录、工程、配置、媒体或历史一律不覆盖，当前不提供合并到已有空间的功能。

备份使用 SQLite backup API，不复制正在使用的单个主数据库文件。源数据库同一只读监视连接的 `data_version` 前后比较，并比较源业务值、复制前后文件树和备份包字节；变化会中止，留下不能认领的未完成副本。数据库/FK完整性、本地文件引用及生产媒体的大小和 SHA256 必须匹配。缺失媒体、外部对象存储、链接/Windows junction 或已绑定空间的数据库不被静默跳过，也不会联网获取文件。正式搬迁应先停止旧服务的写入；检测变化并不能替代跨系统文件快照。

备份包包含敏感配置、可能存在的供应商密钥和用户素材，只能保存在维护者的私有目录。包内写入全忽略规则，防止普通 Git staging 意外收入；该规则不是访问控制。POSIX 新目录为0700，Windows目录权限由维护者设置。公开验证收据只包含计数、校验结果和源码指纹，不包括这些原始资料。

受支持的 `run_controlplane.py` 进程终身持有控制根 OS 锁；每个 `run_tenant_worker.py` 另持有自身空间 OS 锁。认领持有同一根锁和目标空间锁，服务存活时拒绝执行。锁由操作系统随进程结束释放，不靠锁文件存在或猜测PID判断。旧版本未参与该协议的服务必须明确停机，不能把缺少锁当成旧进程已停止的证据。

认领先在控制库持久记录原包标识、manifest hash、明确用户/空间和 `preparing` 状态，再复制到新的待发布目录。源库与备份包不改写。离线副本通过专用的显式认领入口绑定固定空间列和约束，然后在隔离环境中运行受支持的 schema 迁移；不读取主机 `.env`，不启动HTTP或任何模型执行器。原业务字段、不可变JSON、请求标识、预算及未知预留逐项保持；仅schema版本/并发槽位允许正常初始化。已停用总预算表的只读归档按原列校验。

复制文件在发布前显式fsync，支持的平台还刷写目录；这不构成底层存储断电保证。验证通过后将待发布目录一次原子改名到目标。控制库最后置 `complete`；若中断，网关在 `preparing` 时拒绝启动该空间，不会将缺口当成新的空账号数据。原包、账号或意图改变会拒绝恢复。同意图重试可重新制作未发布副本；若已改名但未完成，必须再次验证业务数据和所有文件后才解除门禁。完成后的重放只返回原认领结果，保留后续编辑，不按旧包覆盖。

导入数据库保存不可变的 `workspace_import` 收据，并在worker导入应用前设置执行锁。锁期间所有自动视频、Agent、图片、理解、技术分析与两种导出扫描器均不启动，既有任务状态、请求身份和未知费用保持原样；资料仍可查看和手工编辑；新导出明确显示暂停原因并拒绝入队，已有导出记录及同请求重放保持可读。当前没有网页解锁入口，迁移不能作为恢复收费调用的授权。普通新空间初始化仍拒绝非空未认领数据库。

回退从原始备份包恢复到全新独立目录，不覆盖原入口、已迁入副本或新的编辑。恢复校验数据库与全部文件，不启动任何服务。正式账号切换和恢复运行由维护者按明确归属及执行策略另行处理。
