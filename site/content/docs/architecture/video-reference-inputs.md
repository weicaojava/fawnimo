# 视频参考输入与原项目费用

当前有两个独立输入协议。`seedance25_text_v1` 保留原文字请求、默认指纹与历史控制行为；新增 `seedance25_reference_v1`，实际模型同为 `doubao-seedance-2-5-260628`，但服务档案、执行绑定和费用规则分别核对。视频分类或相同模型名称不会自动授予参考输入权限。模型管理保存用途不会调用模型。

## 明确模式与实际输入

分镜工作室的镜头执行计划支持三种互斥方式：

| 方式 | 当前有界输入 | 顺序 |
| --- | --- | --- |
| 素材参考 | 最多3张 PNG/JPEG，加最多1个 MP4；至少选择一项 | 用户明确排序，保留图片/视频角色 |
| 只指定首帧 | 1张 PNG/JPEG | `first_frame` |
| 指定首帧和尾帧 | 2个明确选择的位置，可选择同一张原图 | `first_frame`、`last_frame` |

新选择保存原项目媒体ID、预期SHA及角色，不接受客户端URL、路径或密钥。旧 `reference_media_ids` 与新选择不能混用；切换模式明确清空当前选择，缺少尾帧时不能伪造完整首尾帧。其余资产媒体保留为来源记录与资产描述，不自动作为图像或视频输入发送。

图片实际解码后须满足每边300–4096像素、最多1600万像素、宽高比0.4–2.5；每张≤4 MiB，素材参考图片合计≤12 MiB。首帧/首尾帧是实际9:16的较窄子集，向服务发送adaptive比例；本地不裁切、拉伸或自动换模式。发送的是同一次读取并核对的原始PNG/JPEG字节，不在HTTP发送前重新找同名文件。

参考视频采用拥有独立进程与时间界限的完整解码：MP4、H264/HEVC、2–10秒、严格24/25/30fps零点连续时钟、边长300–1920、407696–2073600像素、宽高比0.4–2.5、≤32 MiB。非方形像素或旋转元数据不被自动修正。可有一条有界AAC/MP3音轨，记录实际有无声音及样本；不把参考原声当作已经完成配音。解码器在探测和解码时均设置像素上界，父进程负责期限与清理。

参考模式向服务请求9:16、480p、MP4、关闭生成音频、保留水印；首尾帧模式发送adaptive并要求实际输入9:16。接收到可用视频候选不证明服务实际画面质量、人物一致性、配音或水印符合要求。额外模型、任意参数、自动格式回退、音频参考与更多供应商尚未加入。

## 计划、密封证明与单份预留

计划继续使用原剧本、实际镜头、明确资产版本和不可变修订。仅新参考计划使用 `m4b-reference-v1`；旧文档中新字段为null时不进入历史规范化输入，不改变旧请求/绑定哈希。新计划在任何媒体字节哈希前，限制全部来源与显式素材的不同ID≤128、总字节≤64 MiB；跨镜头共用媒体只做一次完整哈希，后续重查原元数据与文件身份。

新准入一次明确提交一个镜头。实际文件读取与解码在writer外；最终事务重查原项目、SHA、文件身份和完整当前执行绑定。同一事务保存真实job、唯一项目预留、共同原生费用批次，以及完整的 `video_reference_input_sets` / `video_reference_inputs`。SQL约束及触发器禁止缺项、稀疏位置、角色错配、归属错配、更新/删除/REPLACE和封存后补项；重复首尾帧位置仍保留独立角色。

工作进程首次发送前重载完整原证明并再次核对实际原字节，随后在短事务内校对原账号、价格、完整财务集合、租约和素材身份，创建真实attempt与unknown费用，再授予交付资格。已变化的未发送素材取消原任务并仅释放已证明未发送的预留；已prepared或已发送的未知费用不因失败、取消意图或ready退还。

仍使用原来的 `native_video`，不增加第七种费用kind。新参考报价必须额外声明 `input_protocol=seedance25_reference_v1`，并覆盖协议允许的最多3张输入图片、1个视频与30秒输出，不能因目前只选一张图或入口暂不支持视频而沿用更小的文字报价。原文字报价省略这个字段，原报价快照和账单不被改写。

## 参考视频交付

图片以实际字节发送；视频不冒充base64输入。管理员的 `reference_media_origin` 必须是独立核对的准确HTTPS根origin；可省略，省略时仅开放图片和首尾帧。回环HTTP仅允许受信测试组合独立注入，不能从模型端口、网页或项目导入推断例外。

视频交付地址由服务生成：`/api/v1/execution-reference-media/{opaque_id}?token=...`。数据库只存token SHA，绑定原job、项目、输入位置与实际prepared attempt；最长1小时、合计最多16次GET/HEAD/单Range读取，取消、完成或失去完整原授权时停止交付。每次核对原文件SHA，一次只占一个响应通道，发送失败或断开也释放。供应商凭据和Cookie不随素材读取转发。

当前独立工作室默认 `/api/v1` 入口可组合该读取服务。固定身份网关另以准确origin、签名和原空间固定worker组合只读交付；内部读取仍通过原 `TenantBoundaryMiddleware`，身份收费网关保持关闭。配置HTTPS origin不等于已经验证供应商可从公网取到视频。应用在路由和访问日志前移除该查询串；反向代理也须采用不记录交付查询串的日志配置。

## 页面与验收边界

新输入预览只展示素材身份、SHA、用途、顺序和固定输出参数，明确标为元数据检查。其 `body` 与 `wire_hash` 保持null，另有摘要哈希；实际图片内容和随机视频交付地址不进入预览，实际解码在接受任务前完成。预览不调用模型、不预留费用、不授予质量资格。

新异步操作使用项目/章节/登录身份及递增页面代次，托管Cookie在发送前和接收结果前重新核对；自己的确认框随原视图失效关闭。原提交记录仍按原空间、项目、计划、镜头和完整确认内容找回，先于当前报价、素材、开关及满额校验。找回后刷新可提交状态，候选仍须在剪辑页单独采用。

身份复验、提交和后续读取失败都不按409/422自动清除原意图；只有成功核对原项目任务后才自动清理。同项目其他标签页的不同待核对记录不能被覆盖或误删。显式清除本地恢复记录须先核对历史、再次确认原身份；它不撤销服务端任务、不释放未知费用，也不授予新请求权限。

当前证据是独立SQLite、自制图片/视频、实际回环HTTP、实际应用和浏览器的软件验证。一个操作者的两个项目不等于两个托管身份；真实供应商、实际账单、真实远程素材交付、全部收费隔离、完整成片和公网部署仍待独立验收。F-007.05保持部分实现，身份收费门禁不因这条协议而开放。

固定身份网关另有默认关闭的[按空间签名交付](../workspace-reference-delivery/)，原工作进程继续核对原任务/字节/期限/16次，不借用浏览器Cookie，不开放收费提交。独立工作室的旧交付地址继续保留。

Wan3.0图片档案另用wan30_reference_v1和独立的两张wan30_reference表，原Seedance声明、行及任务费用不改写。共同服务按原连接的明确协议选择存储家族；两者不能给同一任务混装输入。详见[万相运行时](../wan-video-runtime/)。
