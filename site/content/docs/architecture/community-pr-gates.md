---
title: 准确 PR 审查与 CI 观察
description: 默认关闭的本机维护者门禁、独立身份、准确版本和历史记录。
---

`github_exact_pr_review_v1` 由本机维护者单独配置，只读取并记录准确 PR 的审查和 CI 状态。当前没有提交审查、留言、创建 PR、合并、费用授权或部署操作。默认策略关闭，独立审查账号、可信检查镜像、可信父程序和工作流清单均不自动配置。候选代码、需求文字和候选测试输出不能改变策略。

请求只包含稳定请求键、原变更包、原检查编号和 PR 编号。启用需要维护者指定具体的独立 GitHub 数字账号、开发账号、可信镜像 ID、父程序源码 SHA-256，以及两个固定工作流的准确 Git blob。禁止重复身份和审查/开发账号交集。功能登记即使列出控制程序，也不能扩大候选修改范围。

新观察先核对当前准确本地候选和已通过、已确认清理的原检查，确认镜像及父程序受当前策略信任。工作流 blob 从准确基础/候选 Git 树读取，不采用暂存区或工作树。随后并发读取固定公开需求、公开源码和 PR，以短写事务复查准备记录、评估/计划、选择修订号、功能登记和原公开版本，再向单独审查库追加观察。原请求恢复先于这些新来源门槛，不重复网络读取。

公开观察器仅在固定 `api.github.com` 上进行匿名 GET，核对仓库数字身份、公开状态、PR 的相同仓库基础/头引用及准确提交。父程序拥有固定 45 秒子程序，使用操作系统环境白名单，不提供 Git、模型、API 凭据、个人代理配置或数据库。每个响应最多 1 MiB，最多 32 次请求，审查最多 300 条、运行最多 200 条、每次尝试任务最多 100 条；分页不完整会拒绝。正文、登录名、用户提供的链接与命令都被丢弃，审计只保留必要身份/状态和响应哈希。

任务不依赖 JSON 中可能缺失的 `run_attempt` 字段，而通过固定运行编号及准确尝试编号读取 [GitHub 运行尝试任务接口](https://docs.github.com/en/rest/actions/workflow-jobs#list-jobs-for-a-workflow-run-attempt)。收集结束再次核对审查、运行、工作流可用状态、PR 和 `main`，变化则拒绝该次观察。一次观察不能保证之后状态不变，后续行动必须重新读取。

只有维护者名单中的 `User` 类型且具有仓库成员/协作者/所有者关联的账号可计入审查；PR 创建者与配置中的开发账号不计入。按每人最新有效决定核对准确头提交，旧版本批准、撤销、要求修改或待完成审查都不能通过。中性留言不会成为批准，也不替代已有决定。账号来源必须是 GitHub 观察结果，不能取自请求或候选输出。

两个受信工作流的准确最新运行及其最新尝试必须属于真实 `pull_request` 事件和原 PR/基础/头版本。缺失、排队、运行中、失败、取消、跳过或没有执行必需步骤均阻止通过。相同工作流路径出现不同工作流数字身份时直接拒绝，因为各自的运行序号不能比较；不能用旧高序号的成功掩盖重建后的新失败。工作流规则须同时匹配基础树、候选树及维护者固定的 blob。

本协议只接受准确基础上的单一本地候选提交及当前公开 `main`。实际 PR 检查默认使用临时合并版本，因此还核对其父提交为原基础/候选，且测试树与候选树完全相同。维护修复 PR 的实际触发和等树验证是另外的传输证据，不等于产品候选流程或独立审查已完成。

独立审查库包含固定策略和观察两张业务表，另有 SQLite 内部序列表。策略不能原地改写；变更策略应保留旧历史并建立新的专用根目录。观察用显式整数序号排序，支持重启及 `VACUUM` 后保留顺序。每库最多 384 条、总正文 16 MiB、单条 64 KiB；逻辑替换、物理 rowid 替换、更新和删除均受保护，开启时核对完整已知结构。时钟回退阻止新记录，原记录仍可读取。这些约束不提供同一操作系统身份之间的安全隔离。

结果中的 `eligible_at_observation` 只描述观察时刻；`promotion_authorized`、`merge_authorized`、`deployment_authorized` 始终为 false。恢复结果还明确标记历史用途和行动前重查。可信维护者、安装代码、本机 Git/数据库及 GitHub 服务处于信任边界内。当前实际独立账号审查、生产 GitHub App 联合接入、候选 PR 发布及完整自动研发资格分别保留为未完成，不能用自作账号/CI 数据或作者审阅代替。

操作见[维护指南](../../guide/community-pr-gates/)，执行来源见[固定代码检查](../community-code-checks/)，后续工作见[平台交付计划](../../plans/platform-delivery/)。

维护者另可明确配置[准确候选草稿发布](../community-publication/)。它保存独立意图和原PR追溯，默认关闭，不提交审查或授予合并/部署权限。
