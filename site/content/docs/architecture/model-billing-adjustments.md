当前实现扩展[模型费用账目](../model-accounting/)，仍只处理维护者明确导入的规范化证据，不连接供应商账单或退款接口。原始账单的私有副本和哈希、规范化行、原调用、原结算收据及任务明细均不被覆盖。

## 更正链

`model_billing_corrections` 将新账单行绑定到原收据、原项目、前一更正及当前版本。新账单必须来自另一份已导入凭证，历史供应商、连接版本、账户版本、请求标识和币种与原收据一致。行金额表示该次请求的**更正后总额**。差额为新总额减当前总额；没有更正时当前总额取原收据金额。

`correct_billing_line` 在一次 `BEGIN IMMEDIATE` 中检查原行重放、当前更正版本、上下文及项目余额，原子更新项目已结算额和版本，再追加不可变更正。退减不改项目上限；补记必须使用现有可用额度，不能截断金额或自动提高授权。额度不足保留争议与全额证据，原金额保持不变，维护者通过原项目预算明确调整后才能再核对。高于原报价的事实继续保留报价违规，退减不自动恢复旧费用上界。

同一行与相同决定重放返回原更正，包括后来又有更正时；改原收据、原因或原观察版本会冲突。两个写入者不能同时使用同一更正版本。已入账行不能再次改为重复证据。正常首次对账和完全重复凭证处理继续可用；原账单恢复识别已更正行，不再次收费。

## 歧义归属

多个历史调用具有完全相同的供应商、连接、账户和请求标识时，首次对账仅记录歧义，保留所有未知预留。`model_billing_assignments` 允许维护者在实际匹配集合中明确选择一个仍未知、尚未结算的调用，并记录单行原因。决定不可改归另一调用；相同决定可重放。随后沿用原对账事务结算被选调用，其他项目和调用的预留继续保留。

归属决定只确认选项，不推断真实供应商身份或退款。无歧义、尚未记录歧义、不匹配的账户/请求、已结算调用及已有决定不能被此入口重分配。

## 数据库与读取

新表和上下文、整数、链版本、更新/删除及唯一键保护均为附加迁移，不重写旧记录。保护同时覆盖 SQLite 物理 `rowid` 的替换；观察到的旧核对记录物理键覆盖反例已有修复回归。账单原有五表也安装这一附加保护。维护者及其本机数据库仍属受信边界，并非同一系统管理员之间的权限隔离。

项目读取使用实际 SQLite 读事务，把旧收据、更正链、待核对负债与当前项目余额置于同一个快照。待补入差额以更正后净额为已覆盖金额，避免退减后仍用旧总额抵扣新负债。历史累计金额采用分批读取和 Python 整数求和，HTTP 输出十进制字符串。页面分别展示首次核对金额、当前净额、退减及补记；下方任务明细保留原结算事实。

维护命令继续要求已有有效所有者、固定已认领空间、已升级结构，以及网关和该工作进程的系统维护锁。私有凭证不加入媒体下载记录，页面不返回供应商请求标识或原始证据。操作方法见[更正与归属指南](../../guide/model-billing-adjustments/)。

## 验证边界

本轮使用新建本地账号、自造账单、真实 SQLite/独立进程和实际构建页面验证。没有读取原用户数据、调用收费模型或供应商退款。真实供应商账单认证、真实退款到账、付费生成、独立审核和公网联调继续未验，`provider_bill_verified` 保持 false。
